## 1.5.7 相对 1.5.6 的变化（回应上一轮独立审计）

上一轮审计（针对 1.5.6）提出的问题，经作者方逐项实跑复核后：

**属实并已修复（`tests/regression-1.5.7.mjs` 锁定）：**

1. **二次方程判别式尺度误判**：`solveQuad()` 的容差带 `Math.max(1, …)` 绝对下限，方程整体缩小时（如 `x²−1e-13=0`）真判别式被吞、误报重根 0。修复：纯相对容差 + 系数仅在极端尺度（[1e-100, 1e100] 之外）才归一化——普通整数方程保持原计算路径与精确结果。
2. **方程组行列式下溢**：`solveSystem()` 在系数 1e-200 级时行列式下溢成 0、对角方程组误报无穷多解。修复：行尺度条件归一化（同上，只在极端尺度介入）。
3. **`solveLinear()` 缺有限性守卫**：极端输入下解溢出成 Infinity 被当作结果返回。修复：与 `solveQuad()` 同口径返回「数字太大，超出精确计算范围」错误。

**经复核不属实或属既定口径（未改，回归测试中留有记录）：**

- `toFraction()` 以 1e-10 容差把 `0.3333333333` 识别为 `1/3`：这是全应用统一的分数识别口径（主界面同标准），属产品定版行为。
- `simplifySqrt()` 试除法在大整数下耗时：方程根式路径已有 `sqrtRat()` 的 N≤1e12 上限设计（实测 9 位小数系数 0ms 即返回不可化简）；独立根号页 1e15 级输入实测约 146ms（服务器 Node 环境），在可接受范围。
- 原尺度判别式非有限（溢出/NaN）仍按 1.5.6 口径报错，如 `(1e200, 1e200, 1e200)`——归一化虽可解，但 b² 已溢出，统一报「数字太大」。

## 测试如何运行

本地全套共 **1340 条断言全过**（作者工程内运行，含 paykey 相关部分）。

本仓库可**直接独立运行**的（851 条）：

```bash
node tests/audit-scenarios.mjs      # 84 条
node tests/regression-1.4.17.mjs    # 60 条
node tests/regression-1.5.0.mjs     # 81 条
node tests/regression-1.5.2.mjs     # 112 条
node tests/regression-1.5.5.mjs     # 514 条
```

**依赖未公开模块、公开仓无法独立运行**的（文件内容与作者本地版逐字一致，未做删改）：

- `tests/run-tests.js`、`tests/regression-1.5.4.mjs`、`tests/regression-1.5.6.mjs`、`tests/regression-1.5.7.mjs`：页面测试 harness 需要 `src/common/paykey.js`（未公开）注入；`run-tests.js` 另含收费系统算法断言，以及对作者本地另一项目（乒乓手环应用）密钥模块的交叉隔离校验（含本机绝对路径）。这些断言只能在作者本地复现，公开仓中运行会在读取 paykey.js 处报 ENOENT——这是预期行为，不是测试失败。

## 审查约定

- 结论请区分「确定存在的问题 / 潜在风险 / 已验证正常」，并给出可复现的输入。
- 以下为产品定版行为、不是 Bug：结果能写成精确分数时同屏双显（小数+分数同行，连接号按回读全等取 = 或 ≈）；不采用卡西欧「分数与小数混算结果恒为小数」规则，分数钮是否出现只看结果值；无理根给根式精确形、恢复不了自动回退小数；单位换算「带回计算」带回的是换算过程式（如 `5×2.54`）而非裸结果。
