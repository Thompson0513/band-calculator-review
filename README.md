**第十七轮外部复审修复（2026-11-15，针对提交 839910e4 的复审报告）**

复审先确认第十六轮修复与系数键盘扩键全部独立通过（组合数 BigInt/无 BigInt 双路径扫描零错误、C(56,27) 与键盘输入序列模拟、安装包哈希均对上），新发现 1 点，属实已修：

- SSS 极小边误判退化：(1, 1, 1e-16) 数学上非退化，却返回「三边退化成一条直线」。根因有两层：浮点比较 `srt[1] + srt[2] === srt[0]` 中 1 + 1e-16 圆成 1；兜底的 `sidesDegenerateExact()` 把边长放大成安全整数再比，放大 1e16 超安全整数上限直接放弃。修法：新增 `sidesSumCmp()`——按十进制串用 BigInt 精确缩放比较（次大 + 最小）与最大边，无位数上限，SSS 判定优先走它；无 BigInt 时才退回旧浮点口径。
- 连带修 `fromSSS` 的角度稳定性：半角式的 hs − n[i] 改稳定差形（另两边先拿大的减、再加小的，近邻相减精确）且根号分开相乘防下溢——否则即使放行，(1,1,1e-16) 的三个角也会全算成 0。修复后该三角形给出 (90°, 90°, ≈5.729577951308232×10⁻¹⁵°)、面积 5×10⁻¹⁷，针形三角形一路可算到边长 1e-308。
- 判定语义披露：(0.30000000000000004, 0.1, 0.2) 按十进制语义是 0.3 < 0.30000000000000004，现判「三边不能构成三角形」（旧浮点口径因 0.1 + 0.2 恰等于该双精度值判「退化」）；十进制口径与用户输入串一致。
- 真退化仍拒绝：(1,1,2)、(1,2,3)、(0.1,0.2,0.3) 判退化，(1,1,0) 判零边，(2,3,10) 判不满足三角形不等式，均有断言钉死。

证据：`tests/regression-1.6.0.mjs` §17（21 条）；连带 §12g「1e150 等边给 60°」由钉死具体双精度值改容差断言（稳定差形后同角差 1 ulp），已在原文件标注披露。
