1. **tan() 奇点被 ° 后缀绕过（真 bug，作者方上轮结论错误，特此更正）**：`tan(90°)` 中 ° 后缀先把值换算成弧度并标记 isRad，旧奇点检查（只查角度制裸数字）被绕过，旧版返回 `16331239353195370` 这类大数；`tan(270°)`、`tan(450°)`、`tan(-90°)` 与弧度制 `tan(π÷2)`、`tan(3π÷2)`、`tan(-π÷2)` 同样漏过。1.5.8 的说明中「tan 奇点不属实」是作者方探针只测了不带 ° 的输入所致，**该结论作废**。修复：奇点判定统一落在最终弧度值上（`rad/(π/2)` 距最近奇整数 <1e-12 即判无意义）；`tan(89.9999999999°)` 仍给大有限数不误伤，引擎与页面双层均已锁定。
2. **`gcdLcm()` 入口缺安全整数检查**：旧版 `gcdLcm(9007199254740992, 0)` 直接返回 gcd=9007199254740992。已补入口 `Number.isSafeInteger()` 检查，超限统一报「数字太大，超出精确计算范围」。
3. **`fracCalc()` 入口同样补安全整数检查**：防止输入在解析阶段已被舍入、后检又恰好放过时「算的是另一个数」。

**容差专项（应复审要求补齐证据）**：近重根 δ∈{0, 1e-9, 1e-11, 1e-13} 双侧扫描及 ×1e-8/×1e8 缩放，全部根代回原方程相对残差 <1e-9；方程组分类矩阵补齐另一侧——成比例相容/不相容、近平行唯一解/不相容/相容（含 ×1e6 缩放）、混合量级 1e±100 与 1e-200。δ=1e-15 属浮点模糊带（判别式计算噪声与信号同量级），判重根为已文档化取舍。
