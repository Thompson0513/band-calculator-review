# 手环全能计算器 · 源码审查仓库

小米手环 Vela 快应用《手环全能计算器》，当前版本 **1.5.9（versionCode 48）**，designWidth 336，面向小米手环 8 Pro / 9 Pro / 10 Pro。本仓库供外部独立审查使用，目录结构与真实工程保持一致。

## 文件说明

| 文件 | 内容 |
| --- | --- |
| `src/common/calc.js` | 计算引擎：表达式求值、分数/根式精确形、解方程（一次/二次/方程组）、函数图象数据、单位换算 |
| `src/pages/index/index.ux` | 全部页面与交互逻辑（Vela 快应用单页源码，含显示层格式化与布局） |
| `src/manifest.json` | 应用清单（包名 com.muse.calc，含 DEVICE_INFO 权限声明） |
| `tests/` | 全套 Node 回归测试（见下方「测试如何运行」） |
| 安装包 | 编译后的 `.rpk`（即发售成品，与上述源码对应）：[下载 calc-1.5.9.rpk](https://muse.ai/files/1321696044366246/2429386811168436/nyk8n47souxgpm2bm50z5h0g/___1.5.9.rpk)（链接有效期至 2026-11-16，过期请联系作者刷新） |

付费校验模块 `src/common/paykey.js` **不在本仓库内**（商业机密），页面源码中只有对它的函数名引用。因此涉及该模块的少数测试无法在公开仓独立运行，详见下方说明。

## 1.5.9 相对 1.5.8 的变化（回应第五轮独立复审）

经作者方逐项实跑复核（`tests/regression-1.5.9.mjs` 锁定，63 条）：

**属实并已修复：**

1. **tan() 奇点被 ° 后缀绕过（真 bug，作者方上轮结论错误，特此更正）**：`tan(90°)` 中 ° 后缀先把值换算成弧度并标记 isRad，旧奇点检查（只查角度制裸数字）被绕过，旧版返回 `16331239353195370` 这类大数；`tan(270°)`、`tan(450°)`、`tan(-90°)` 与弧度制 `tan(π÷2)`、`tan(3π÷2)`、`tan(-π÷2)` 同样漏过。1.5.8 的说明中「tan 奇点不属实」是作者方探针只测了不带 ° 的输入所致，**该结论作废**。修复：奇点判定统一落在最终弧度值上（`rad/(π/2)` 距最近奇整数 <1e-12 即判无意义）；`tan(89.9999999999°)` 仍给大有限数不误伤，引擎与页面双层均已锁定。
2. **`gcdLcm()` 入口缺安全整数检查**：旧版 `gcdLcm(9007199254740992, 0)` 直接返回 gcd=9007199254740992。已补入口 `Number.isSafeInteger()` 检查，超限统一报「数字太大，超出精确计算范围」。
3. **`fracCalc()` 入口同样补安全整数检查**：防止输入在解析阶段已被舍入、后检又恰好放过时「算的是另一个数」。

**容差专项（应复审要求补齐证据）**：近重根 δ∈{0, 1e-9, 1e-11, 1e-13} 双侧扫描及 ×1e-8/×1e8 缩放，全部根代回原方程相对残差 <1e-9；方程组分类矩阵补齐另一侧——成比例相容/不相容、近平行唯一解/不相容/相容（含 ×1e6 缩放）、混合量级 1e±100 与 1e-200。δ=1e-15 属浮点模糊带（判别式计算噪声与信号同量级），判重根为已文档化取舍。

**测试可复现性（应复审要求改进）**：见下方「测试如何运行」——公开可独立运行断言由 851 条提升至 **1408 条**。

## 1.5.8 相对 1.5.7 的变化（回应上一轮独立审计的 15 项清单）

经作者方逐项实跑复核（`tests/regression-1.5.8.mjs` 锁定）：

**属实并已修复：**

1. **判别容差过粗**：相对容差 1e-12 时，`{x+y=2; x+(1+1e-13)y=2+1e-13}`（真唯一解）误判无穷多解、`x²+2x+(1−1e-13)`（真两根）误判重根。浮点噪声实际只有 1e-16 级，`solveQuad()` 与 `solveSystem()` 的容差同步收紧到 1e-14，全部旧噪声守卫实测不回退。
2. **`solveSystem()` 缺有限性守卫**：NaN/Infinity 输入旧版一律落「无解」分支。已加入口与结果守卫，统一返回「数字太大，超出精确计算范围」；`solveLinear()` 顺带补中间量守卫（防 Inf−Inf=NaN 被当解）。
3. **`fracCalc()` 中间乘积提前溢出**：乘除改交叉约分、加减先约分母 gcd，如 `1000000000/1000000001 × 1000000001/1000000000 = 1` 不再误报；真溢出仍报错。
4. **根式自检容差对极小根偏宽**：`quadRadStrs()`/`quadImRad()` 的数值自检由 `1e-9·max(1,|v|)` 改为 `1e-9·|v|+1e-12`。

**经复核不属实（证据已写入回归测试）：** tan() 奇点（**此条已在 1.5.9 更正：仅指不带 ° 的裸数字输入；带 ° 输入旧版确有问题，已修**）；隐含乘法（输入层已补 ×，`2sin(30)=1`、`2√(9)=6` 页面实测通过）；`evaluate()` 返回 Infinity（「=」键对「溢出」结果明确拦截，不记历史、不污染 Ans）；绘图渐近线连线（绘图为 90 点点绘、无连线段，|y|>1e6 跳点）；历史存储损坏（已有 try/catch＋JSON 容错＋条目过滤）；`gcdLcm()` 安全整数（早已有守卫）。

**已定版取舍（未改）：** 原尺度判别式非有限仍先报错（如 `(1e200,1e200,1e200)`，b² 已溢出成 NaN）；`toFraction()` 的 1e-10 容差为全应用统一口径；数据单位 KB/MB 按 1024（与国内信息技术教材口径一致）。

（1.5.7 的变化——二次方程判别式尺度误判、方程组下溢、`solveLinear()` 守卫——见 git 历史与 `tests/regression-1.5.7.mjs`。）

## 测试如何运行

本地全套共 **1447 条断言全过**（作者工程内运行，含 paykey 相关部分）。

本仓库可**直接独立运行**的（**1408 条**，已实测）：

```bash
node tests/run-tests.js             # 151 条（另 39 条收费系统断言测未公开模块本身，自动 SKIP 并打印提示）

node tests/regression-1.5.2.mjs     # 112 条
node tests/regression-1.5.4.mjs     # 61 条
node tests/regression-1.5.5.mjs     # 514 条
node tests/regression-1.5.6.mjs     # 77 条
```

带 `[审查仓适配]` 注释的少量代码是公开仓与作者本地版的**唯一差异**：`paykey.js` 缺失时，页面 harness 类测试改用惰性桩拼装页面（这些断言不涉及付费校验行为，桩不影响结果）；`run-tests.js` 中直接测 `paykey.js` 本身的 39 条断言无法桩代，运行时打印 SKIP 跳过。桩源代码就在适配注释旁，可直接核查。其余断言逻辑与本地版逐字一致。

## 审查约定

- 结论请区分「确定存在的问题 / 潜在风险 / 已验证正常」，并给出可复现的输入。
- 以下为产品定版行为、不是 Bug：结果能写成精确分数时同屏双显（小数+分数同行，连接号按回读全等取 = 或 ≈）；不采用卡西欧「分数与小数混算结果恒为小数」规则，分数钮是否出现只看结果值；无理根给根式精确形、恢复不了自动回退小数；单位换算「带回计算」带回的是换算过程式（如 `5×2.54`）而非裸结果。
